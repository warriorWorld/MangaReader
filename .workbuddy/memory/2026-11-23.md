# 2026-11-23

## Fixed file-name number sorting (MangaReader + ILocal)

Rule (user-specified): take the file name, strip the extension, drop every non-digit
character, and compare the remaining digits as a number (`60story48(112)` -> `6048112`).
If there is no number, don't sort.

**MangaReader** (`app/.../mangareader/sort/`, `business/detail/LocalMangaDetailsActivity`)
- Added `FileNameNumberUtil` (getFileName / getNumbers / hasNumber / compareNumbers /
  compareDigits) — digit-string compare, no int/long overflow.
- Added `FileNumberComparator implements Comparator<MangaBean>` (sorts by `url`, or by
  `localThumbnailUrl` with `sortByThumbnail=true`).
- Deleted the four old comparators (FileComparator, FileComparatorAllNum,
  FileComparatorWithBracket, FileComparatorDirectory) — the fragile `_`/`-`/`(` heuristics.
- `sortFiles()` now sorts `mangaList` itself (no more positional re-assignment of
  `localThumbnailUrl`, which used to leave `url` mismatched) and rebuilds `pathList` from it.
  `pathList` is filled before any early return so ReadMangaActivity still receives pages.
- `initFile()`: null `mangaList` guard + `initGridView()` in catch (was silently swallowed).

**ILocal** (`launcher/.../image/local/sort/`)
- Same `FileNameNumberUtil` in Kotlin; `FileComparator` rewritten; `ImageSorter` collapsed
  into one concrete class (`sortImages(MutableList<ImageBean>)`, skips when no item has a number).
- Deleted UnderlineSorter / BracketSorter / AllNumSorter / FileComparatorAllNum /
  FileComparatorWithBracket and the `setNextSorter` chain; `ImageListViewModel` now holds
  a single `imageSorter`.

Notes: MangaReader needs minSdk 21 -> avoid `List.sort`, use `Collections.sort`.
The old comparators mutated int fields per instance and relied on split markers, which is
what broke after earlier edits.
